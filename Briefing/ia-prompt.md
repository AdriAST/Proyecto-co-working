# Auditoría del briefing mediante IA - LifeOS

## Prompt utilizado

> Actúa como consultor de proyectos software. Revisa nuestro briefing. Identifica información ambigua, objetivos mal definidos, restricciones no contempladas, riesgos y preguntas que deberíamos realizar antes de iniciar el desarrollo. No propongas soluciones todavía.

## Análisis de la respuesta

### Información ambigua

* No está completamente definido qué funcionalidades serán obligatorias para el MVP y cuáles podrán desarrollarse posteriormente.
* No se ha definido con exactitud cómo se almacenarán los datos.
* No está claro si la aplicación tendrá diferentes tipos de usuarios o solamente un usuario local.
* El funcionamiento exacto del dashboard todavía no está definido.

### Objetivos que podrían concretarse

Los objetivos están definidos de forma general, pero algunos podrían concretarse más. Por ejemplo, "centralizar diferentes funciones de organización" no indica exactamente qué funciones deben estar terminadas para considerar que el objetivo se ha cumplido.

También sería necesario definir mejor qué información debe mostrar el dashboard y qué se considera una aplicación suficientemente sencilla de utilizar.

### Restricciones no contempladas

* El tiempo necesario para aprender o investigar nuevas tecnologías si aparecen problemas durante el desarrollo.
* La posible dificultad de desarrollar todas las funcionalidades de forma individual.
* Las limitaciones que pueda tener el almacenamiento de datos.
* La compatibilidad de la aplicación con diferentes navegadores y tamaños de pantalla.
* El tiempo necesario para realizar pruebas y corregir errores.

### Riesgos

* Que el proyecto sea demasiado grande para el tiempo disponible.
* Que alguna de las funcionalidades resulte más complicada de desarrollar de lo esperado.
* Que se produzcan errores al guardar o recuperar los datos.
* Que la aplicación termine teniendo demasiadas funcionalidades y sea difícil de mantener.
* Que no haya suficiente tiempo para realizar pruebas antes de la entrega.

### Preguntas que deberíamos realizar

* ¿Cuál es la fecha exacta de entrega del proyecto?
* ¿Qué funcionalidades son obligatorias para el MVP?
* ¿Se pueden utilizar librerías externas o debemos utilizar únicamente JavaScript Vanilla?
* ¿Es necesario implementar un sistema de usuarios y autenticación?
* ¿Qué información debe mostrar exactamente el dashboard?
* ¿Qué sistema de almacenamiento de datos debemos utilizar?
* ¿Qué requisitos concretos de protección de datos debemos cumplir?
* ¿Es necesario que la aplicación funcione correctamente en móvil?
* ¿Qué navegadores debemos tener en cuenta?
* ¿Qué documentación es obligatoria para la entrega?

## Conclusión

La revisión muestra que la idea general de LifeOS está bastante definida, pero todavía hay algunos aspectos que deben concretarse antes de comenzar el desarrollo.

Los principales puntos pendientes están relacionados con el alcance del MVP, el almacenamiento de datos, los requisitos técnicos, el funcionamiento del dashboard y el tiempo disponible para realizar el proyecto.

Este análisis se utilizará para aclarar estos puntos antes de comenzar el desarrollo.
